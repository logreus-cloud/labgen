# Участие в проекте

Спасибо, что заглянули. Проект маленький, порог входа низкий.

## Локальная разработка

```bash
git clone https://github.com/logreus-cloud/labgen
cd labgen
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest -q
ruff check labgen tests
```

Собрать пример и посмотреть результат:

```bash
labgen init sandbox
labgen build sandbox/report.md
```

## Что особенно нужно

- **Требования вашей кафедры.** Если labgen оформляет что-то не так, как требует
  ваш методкабинет, — заведите issue и приложите методичку (или её скриншот).
  Такие отчёты ценнее любой абстрактной фичи.
- **Готовые `labgen.yaml`** под конкретные вузы — их можно собирать в `examples/`.
- Пункты из раздела «Что дальше» в README.

## Правила

- Код и комментарии — на русском или английском, главное единообразно внутри файла.
- Новое поведение сопровождается тестом в `tests/`. Тесты проверяют получившийся
  документ (текст абзацев, стили, счётчики), а не внутренности рендерера.
- `ruff check` должен проходить; длина строки — 100 символов.
- Меняете формат по умолчанию — приведите пункт ГОСТ 7.32-2017 или методички
  в описании PR. Значения по умолчанию должны оставаться «как в стандарте»,
  всё остальное настраивается через `labgen.yaml`.

## Issue

Опишите, что ожидали получить и что получилось. Если дело в оформлении — приложите
исходный `.md`, ваш `labgen.yaml` и, по возможности, скриншот проблемного места документа.
