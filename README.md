# labgen

**Пишете отчёт в Markdown — получаете DOCX, оформленный по ГОСТ 7.32-2017.**

Титульный лист, поля страницы, Times New Roman 14 пт, полуторный интервал, абзацный отступ
1,25 см, сквозная нумерация рисунков, таблиц и листингов, автонумерация разделов и содержание,
которое Word собирает сам. Ни одного ручного клика по вкладке «Главная».

> *A CLI that turns a Markdown file into a Word report formatted to GOST 7.32-2017 —
> the Russian academic standard for lab reports and research papers.*

```
labgen init            # создать labgen.yaml и заготовку отчёта
labgen build report.md # получить report.docx
```

---

## Зачем

Оформление отчёта по ГОСТу — это два часа возни со стилями Word на каждую лабораторную:
отступы, интервалы, «Рисунок 3 — ...» с ручной перенумерацией после того, как вы вставили
рисунок в середину, содержание, которое разъехалось. Содержательная часть работы при этом
занимает столько же времени, сколько её оформление.

labgen забирает оформление на себя. Вы пишете текст, он выдаёт документ, который можно сдавать.

```

## Быстрый старт

```bash
labgen init            # создаст labgen.yaml, report.md и папку images/
```

Заполните `labgen.yaml` данными кафедры и своими — один раз на весь семестр:

```yaml
title_page:
  university: ФГБОУ ВО «Название университета»
  faculty: Факультет информационных технологий
  department: Кафедра программной инженерии
  discipline: Базы данных
  author:  { name: Иванов И. И., group: ПИ-21 }
  supervisor: { name: Петров П. П., position: доцент, к.т.н. }
  city: Москва
  year: 2026
```

Тема и номер работы меняются от лабы к лабе — их удобно держать прямо в отчёте,
в блоке front matter:

```markdown
---
work_kind: по лабораторной работе № 3
topic: Проектирование схемы данных в MongoDB
---

# Введение

Цель работы — ...
```

Собрать:

```bash
labgen build report.md
#   конфигурация: labgen.yaml
#   + report.docx
#   рисунков: 4, таблиц: 2, листингов: 3
```

Откройте `report.docx` и нажмите **F9**, чтобы Word собрал содержание.

## Что labgen делает с вашим Markdown

| В Markdown | В документе |
|---|---|
| `# Теоретическая часть` | «1 Теоретическая часть» — с новой страницы, полужирным |
| `## Основные понятия` | «1.1 Основные понятия» |
| `# Введение`, `# Заключение` | без номера — список таких заголовков настраивается |
| `![Схема алгоритма](images/scheme.png)` | рисунок по центру, ужатый до ширины текста, + «Рисунок 1 — Схема алгоритма» |
| строка `Таблица: Замеры` перед таблицей | «Таблица 2 — Замеры» слева над таблицей |
| строка `Листинг: Подключение к БД` перед кодом | «Листинг 1 — Подключение к БД», код — Courier New 12 пт |
| ```` ```python caption="Сортировка" ```` | то же самое, подпись прямо в блоке кода |
| `- пункт` | перечисление через тире, с абзацного отступа |
| `**жирный**`, `*курсив*`, `` `код` `` | сохраняются |

Нумерация рисунков, таблиц и листингов — сквозная по всему документу и пересчитывается
при каждой сборке. Вставили рисунок в середину — просто соберите заново.

## Команды

```
labgen init [КАТАЛОГ] [--force]   создать labgen.yaml, report.md и images/
labgen build ИСХОДНИК.md          собрать документ
    -o, --output ФАЙЛ             куда сохранить (по умолчанию — рядом с исходником)
    -c, --config labgen.yaml      явный путь к конфигурации
    --title / --no-title          печатать титульный лист
    --toc / --no-toc              вставлять содержание
    --strict                      считать предупреждения ошибками (удобно в CI)
```

Конфигурация ищется сама: рядом с md-файлом, затем в текущем каталоге.

## Настройка оформления

Требования кафедр расходятся с ГОСТом — почти всё в `format` можно поправить:

```yaml
format:
  font: Times New Roman
  size: 14
  line_spacing: 1.5
  first_line_indent: 1.25                              # абзацный отступ, см
  margins: {left: 30, right: 15, top: 20, bottom: 20}  # поля страницы, мм
  page_numbers: true
  page_number_position: bottom-center   # bottom-center | bottom-right | top-center | top-right
  section_page_break: true              # каждый раздел с новой страницы
  number_headings: true                 # автонумерация 1, 1.1, 1.1.1
  unnumbered_headings: [введение, заключение, список использованных источников]
  code: {font: Courier New, size: 12, line_spacing: 1.0}
  table: {size: 12}
  captions: {figure: Рисунок, table: Таблица, listing: Листинг, dash: '—'}
```

Например, если на вашей кафедре правое поле 10 мм, а разделы идут подряд:

```yaml
format:
  margins: {left: 30, right: 10, top: 20, bottom: 20}
  section_page_break: false
```

## Как это устроено

Markdown разбирается [markdown-it-py](https://github.com/executablebooks/markdown-it-py),
документ собирается [python-docx](https://github.com/python-openxml/python-docx).
Содержание — это поле `TOC` внутри OOXML, поэтому Word пересобирает его сам, а номера
страниц остаются живыми. Заголовки используют встроенные стили `Heading N`, переопределённые
под ГОСТ, — за счёт этого работает и навигация по документу, и сборка содержания.

Никакого LaTeX, Pandoc и установки Word не требуется — только Python.
